Sandbox Dynamic Pool 是一个运行在 OpenKruise Agents 之上的外置控制器。 它根据请求需求和实际补货能力调整 SandboxSet 库存，让用户请求尽量只领取 已经 Ready 的沙盒。

核心转换 请求路径冷创建
→ SandboxSet scale 0→1
→ Ready 后领取
01 / What it is

项目围绕动态库存建立完整控制闭环

项目连接 OpenKruise 的领取生命周期与 SandboxSet 库存，通过需求观测、目标计算、 自动补货和缩容回落，让用户请求优先获得已经 Ready 的沙盒。

01

需求驱动

按模板汇总近期请求，计算应该保留多少 Ready 库存，而不是为每个请求单独创建沙盒。

02

供给保护

结合补货时延、最大并发补货数和超时状态，限制每轮实际放行的扩容量。

03

自动回落

需求消退后自动回落并 scale to zero；下一次真实请求会再次触发 0→1 唤醒。

02 / Runtime contract

缺货请求进入预热池唤醒流程

OpenKruise 负责 Ready-only 领取和需求记录，Dynamic Pool Controller 负责把需求 转换为 SandboxSet 扩容，两者组成一个清晰的 0→1 运行契约。

领取契约
SandboxSet 没有 Ready 库存时，领取入口拦截请求并记录目标池需求。

Ready-only / createOnNoStock=false 保证请求只领取预热库存； 缺货需求关联到目标 SandboxSet。Controller 收到信号后扩展库存，Sandbox 在池内 完成 Ready，随后请求继续领取。

03 / Side-by-side simulation

同一波请求，固定池和动态池会发生什么

05 / Responsibility boundary

三方协作，但边界必须清楚

OpenKruise 提供领取与 Sandbox 生命周期，外置 Controller 专注需求聚合、库存计算、 供给保护和 SandboxSet 扩缩容。

OpenKruise Agents

拦截冷创建

只从 Ready 库存领取；缺货时不直接创建业务 Sandbox，并暴露可关联到 SandboxSet 的需求信号。

Dynamic Pool Controller

计算并补货

汇总需求、学习补货时延、计算理想库存与实际库存目标，并更新 SandboxSet.spec.replicas。

Caller / Gateway

等待或重试

显式选择禁止缺货冷创建；在库存 Ready 后继续领取，不把失败请求绕回普通冷创建路径。

06 / Control model

控制回路围绕四类信息工作

Controller 通过 Kubernetes 对象获取需求和供给快照，计算目标库存并驱动 SandboxSet 扩缩容。

DEMAND

请求信号

SandboxClaim、成功领取记录，以及领取入口记录的缺货需求。

SUPPLY

库存状态

Sandbox 的 Ready、Creating、创建时间和补货完成时间。

DECISION

库存算法

结合需求速率、补货分位数、允许等待时长、安全库存和供给并发。

ACTUATOR

SandboxSet

把最终实际库存目标写入 spec.replicas，由 OpenKruise 完成创建。

原始库存目标 = 向上取整( 需求速率 × 最大值(补货时长 − 允许等待时长, 0) + 服务系数 × √(需求速率 × 补货时长) ) + 安全底仓
理想库存目标 = 限制在区间(原始库存目标, 最小库存, 最大库存)
01 · 确定性库存

覆盖补货缺口

需求速率 × 最大值(补货时长 − 允许等待时长, 0) 表示补货期间扣除可等待时间后，预计还需要立即承接的请求数量。

02 · 随机安全库存

吸收流量波动

服务系数 × √(需求速率 × 补货时长) 为泊松近似下的波动余量。目标服务分位数越高，服务系数越大。

03 · 固定底仓

抵御模型误差

安全底仓 是额外保留的固定实例数，用来覆盖短窗口少计、调度抖动和补货样本不足等误差。

变量分别代表什么

需求速率近期每秒请求数，来自需求时间窗口的统计。
补货时长Sandbox 从创建到 Ready 的时间，通常取历史 P95 等保守分位数。
允许等待业务允许用户等待库存的最长时间；允许等待越久，确定性库存可以越小。
服务系数目标服务分位数对应的标准正态系数，例如 P99 约为 2.33。
安全底仓额外保留的固定库存，由运维结合模板稳定性和流量误差配置。

数值例子

假设需求速率为 2 次/秒、补货时长为 40 秒、允许等待 10 秒、目标 P99（服务系数约 2.33）、安全底仓为 2。

确定性库存2 × (40−10) = 60
随机安全库存2.33 × √80 ≈ 20.8
向上取整 + 安全底仓向上取整(80.8) + 2
最终理想库存目标 = 83

理想库存还不是本轮真正写入的副本数

公式先给出需求侧的理想库存目标。Controller 还会根据最大并发补货数、当前补货中数量 和供给超时计算可创建槽位，得到实际库存目标，避免一次扩容压垮调度器或镜像仓库。

可创建槽位 = 最大值(0, 向下取整(最大并发补货数 × 利用率) − 补货中数量) · 实际库存目标 = 最小值(理想库存目标, 最大值(当前库存目标, 实际副本数 + 可创建槽位))
07 / Operating modes

项目提供三层动态库存能力

从请求到达到库存 Ready，控制器同时管理唤醒速度、库存规模和供给安全。

按需唤醒

Scale 0→1

空闲期库存归零；缺货请求记录需求并唤醒 SandboxSet，Ready 后完成领取。

动态定容

按流量扩缩

结合需求速率、补货时延、允许等待时长和安全库存，持续计算合理的库存目标。

供给保护

安全补货

通过并发槽位、补货分位数和超时状态限制实际库存目标，避免突发扩容压垮底层供给。
